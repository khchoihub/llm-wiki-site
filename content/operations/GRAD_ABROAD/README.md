# GRAD/ABROAD 나무위키형 서술 문서 전환 지침

이 문서는 `GRAD/`와 `ABROAD/`의 기존 77개 분석노트를 내부 독자가 처음부터 읽을 수 있는 서술형 위키 문서로 전환하는 최상위 작업 규격이다. 두 프로젝트는 정책학 `wiki/`와 독립되어 있으며, 외부 웹 검색으로 내용을 보충하지 않는다.

이 작업의 핵심은 코퍼스의 분포를 요약하는 것이 아니라, 제한 커뮤니티에 묻혀 있는 고급 경험담·제도 운용의 디테일·당사자의 판단·내부 논쟁을 발굴해 하나의 해설 문서로 재구성하는 것이다. 게시물 수가 많다는 사실보다 한 게시물이 무엇을 구체적으로 설명하는지가 중요하다.

> **현행 규격은 V4이다.** 이 문서의 M0~M9와 V3의 다이아몬드 채굴 절차는 유지하되, 실제 출력 문체·굵은 글씨·각주 서술과 완료 판정은 `V4_PIPELINE.md`가 우선한다. V2 감사에서 단순 메타데이터 상위 정렬은 기준 앵커 3개 중 1개만 상위 30위 안에서 찾았으므로, 다중경로 발견·정보단위 장부·적대적 반론 검색도 계속 생략할 수 없다.

5. 한 세션의 기본 단위는 문서 하나다.
6. DB는 SQLite URI `mode=ro`로 연다.
7. 기존 파일명·경로·문서ID·원본건수·password·내부링크 대상을 보존한다.

9. 미완료 작업은 `HANDOFF_TEMPLATE.md`로 인계한다.
10. 사용자가 따로 지시하지 않으면 색인·커밋·push·배포를 하지 않는다.

## M0 — 최종 문서 정체성

### 1. 목적

독자가 주제의 구조, 실제 작동 방식, 당사자의 이해관계, 관행의 이유, 쟁점, 조건과 예외를 구체적으로 이해할 수 있는 내부용 해설 문서를 만든다. 자료를 가치중립적인 통계 대상으로 멀리서 묘사하지 않고, 편집자가 정보가치가 높은 사실과 해석을 선별해 전면에 배치한다.

### 2. 입력 자료

대상 개념노드, 대응 DB 게시물, 필요한 댓글, 관련 노드, 관문 문서.

### 3. 작업 절차

최종 문서는 편집자의 선별과 판단을 전제한다. 다만 그 판단은 원문에 없는 사건을 만들거나 특정 경험을 전체로 일반화하는 자유가 아니라, 어떤 디테일이 독자의 이해와 판단에 중요한지를 결정하는 자유다.

모든 핵심 주장을 다음 네 층으로 분류한다.

- 개인 경험: `한 작성자는 …라고 보고했다.`
- 반복 경험: `여러 게시물에서는 …가 반복적으로 언급된다.`
- 커뮤니티 통념: `게시판에서는 대체로 …로 받아들이는 경향이 있다.`
- 편집자 종합: `이 사례들을 종합하면 …의 차이로 정리할 수 있다.`

개인 경험이라도 작동 원리, 의사결정, 조직 내부의 상호작용을 구체적으로 보여주면 핵심 본문에 쓸 수 있다. 이때 `한 현직자의 설명에 따르면`처럼 범위를 표시하면 된다. 반대로 수백 건에서 반복되는 피상적 질문은 문서의 중심이 될 필요가 없다.

`우세`, `대다수`, `일반적`은 분포가 확인된 경우에만 쓰되, 최종 문서의 목적을 분포 보고로 축소하지 않는다. 문서 서두에는 장문의 면책 대신 자료 범위 한 문장만 둔다.

### 4. 산출물

자료 범위 문장, 인식론적 수준, 정보가치 등급이 부여된 핵심 주장 목록.

### 5. 완료 조건

문장만 읽어도 사건 보고, 반복 관찰, 통념, 편집자 종합을 혼동하지 않으며, 각 대절에 독자가 새롭게 배울 구체 정보가 존재한다.

### 6. 금지사항

단일 경험의 일반화, 공식 규정처럼 단정, 외부 웹 보충, 조롱·편견·독자 훈계, 코퍼스의 빈도만 보고하는 무내용한 중립주의.

### 7. 다음 모듈과의 연결

주장 수준을 M1의 목차와 M3의 각주 강도에 반영한다.

## M1 — 문서 구조

### 1. 목적

현재의 분석 과정 중심 5개 섹션을 독자가 실제 구조와 쟁점을 파악할 수 있는 논제 중심 목차로 바꾼다.

### 2. 입력 자료

기존 섹션, 핵심 명제, 시계열·논쟁 목록, 관련 링크, 원본 규모.

### 3. 작업 절차

기존 섹션은 다음과 같이 해체한다.

| 기존 섹션 | 최종 처리 |
|---|---|
| 반복되는 핵심 질문·이슈 | 주제별 2·3단계 목차의 재료 |
| 통용되는 답·통념 | 해당 주제 본문의 일반론 |
| 시기별 변화 양상 | 실제 변화가 있는 주제 아래 또는 별도 변화 절 |
| 카테고리 정밀도 관찰 | 원칙적으로 근거 장부로 이동 |
| 미해결 지점·향후 과제 | 독자에게 필요한 경우 논쟁·확인되지 않은 점으로 변환 |

기본 흐름은 `개요 → 핵심 구조·작동 원리 → 행위자별 이해관계 → 조건별 차이 → 대표 사례 → 반론과 예외 → 실제 시기 변화 → 관련 문서`다. 자료가 없는 절은 만들지 않는다.

목차는 `무엇이 많이 언급되는가`가 아니라 다음 질문에 답하도록 만든다.

- 실제로 무엇이 어떻게 운영되는가.
- 당사자는 어떤 선택지와 제약을 갖는가.
- 표면적 지표와 실제 결과가 왜 달라지는가.
- 누가 이익과 비용을 부담하는가.
- 통념이 깨지는 조건은 무엇인가.
- 구체 사례가 기존 설명을 어떻게 수정하는가.

- 대형: 2단계 목차 5~9개, 필요할 때만 3단계 목차
- 중형: 2단계 목차 3~6개
- 소형: 개요 포함 2~4개
- 리뷰코퍼스: 잔여 코퍼스 성격, 반복 질문군, 상위 노드 보완점, 데이터 한계

문서 역할은 다음처럼 구분한다.

- 관문: 프로젝트 설명과 대주제 탐색 경로
- 대주제: 분야 구조와 하위 주제 관계
- 세부 노드: 한 주제의 조건·사례·예외·변화

### 4. 산출물

새 목차와 기존 항목의 이동표.

### 5. 완료 조건

각 절이 독립된 독자 질문에 답하고, 최소 하나의 작동 원리·실무 디테일·의사결정상 함의를 제공한다.

### 6. 금지사항

기존 5개 제목의 단순 개명, 빈 절 추가, 모든 연도의 기계적 나열, 관문에 세부 사례 복제, `반복된다·두드러진다·논의된다`만으로 끝나는 목차와 문단.

### 7. 다음 모듈과의 연결

확정된 절별로 M2 문체와 M3 각주를 적용한다.

## M2 — 서술 문체

### 1. 목적

불릿형 보고서를 편집자의 판단과 고급 원자료의 디테일이 살아 있는 백과사전식 연속 설명문으로 바꾼다.

### 2. 입력 자료

기존 불릿, DB 원문, 은어 목록, 근거 장부의 조건·입장·예외.

### 3. 작업 절차

한 문단은 원칙적으로 `편집자의 핵심 판단 → 구체 작동 방식 → 당사자에게 생기는 결과 → 조건·반론 → 사례와 각주` 순서로 쓴다. 같은 논지의 불릿은 합치고 서로 다른 논지는 분리한다. 문서에는 두 서술층을 둔다. 본문은 논지를 끊김 없이 전개하고, 각주는 본문에 넣으면 곁가지가 되지만 버리기에는 아까운 세부 절차·원문의 비유·용어의 뉘앙스·작은 반례·후일담·출처 한계를 맡는다.

주제문은 `타임 관련 조직문화가 반복된다`처럼 소재를 분류하는 문장이 아니라 `공개된 타임은 업무량 기록을 넘어 동료 감시와 업무배분 경쟁을 만드는 인사정보로 작동한다`처럼 그 자료가 밝혀 주는 바를 말해야 한다.

표준 문장 유형:

- 통념: `게시판에서는 대체로 A로 보는 경향이 있다.`
- 조건: `다만 이는 B인 경우에 주로 성립한다.`
- 반론: `이에 대해서는 C를 더 중요하게 보아야 한다는 반론도 반복된다.`
- 예외: `반면 D 조건에서는 반대 사례가 보고된다.`
- 변화: `초기에는 E가 중심이었으나, F년 이후에는 G가 더 자주 논의되었다.`
- 불확실성: `자료만으로는 일시적 현상인지 장기 변화인지 판단하기 어렵다.`

고급 게시물을 사용할 때는 다음 디테일 가운데 가능한 것을 본문에 남긴다.

- 제도의 실제 절차·집계 방식·적용 단위
- 행위자가 선택한 행동과 그 이유
- 기대한 효과와 실제 부작용
- 공식 명분과 당사자가 체감한 기능의 차이
- 동일 지표가 서로 다른 유형의 사람에게 뜻하는 바
- 반론이 겨냥하는 구체 전제
- 사건 이후의 선택과 결과

은어는 실제로 반복되고 이해에 필요할 때만 보존한다. 최초 1회 `컨펌(인턴 이후 정식 채용을 확정하는 것을 가리키는 게시판 표현)`처럼 설명한다.

`흥미롭다`, `주목할 만하다`, `명백하다`, `압도적이다` 같은 AI 평가체는 관찰 가능한 차이로 바꾼다. `몰락`, `천국`, `최악` 같은 표현은 실제 게시판 표현임을 밝혀야 한다.

굵은 글씨는 장식이 아니라 회수 지점으로 쓴다. 대절의 결론, 혼동하기 쉬운 구분, 반론 뒤에도 남는 판단에만 사용한다. 인용부호와 백틱은 원문 표현에, 굵은 글씨는 편집자의 결론에 쓴다. 한 문단에 여러 강조를 흩뿌리거나 수치·기관명·감정적 표현만 굵게 만들어서는 안 된다.

### 4. 산출물

불릿보다 문단이 중심이며, 원자료의 핵심 디테일과 편집자의 해석이 결합된 연속 설명문.

### 5. 완료 조건

모든 가치판단의 주체·기간·범위가 드러나고, 각 대절을 읽은 뒤 독자가 설명 가능한 메커니즘이나 실무 차이를 하나 이상 얻게 된다.

### 6. 금지사항

AI 상투어, 설명 없는 은어, 집단의 본질적 성격 단정, 극적 표현의 재생산, 근거 없는 인과관계, `많다·적다·반복된다`만 남기고 원자료의 디테일을 삭제하는 요약.

### 7. 다음 모듈과의 연결

구체 문장과 범위를 M3에서 감사한다.

## M3 — 근거와 각주

### 1. 목적

각주를 AI가 존재하지 않는 사건·수치·추세를 추가하지 못하게 하는 추적 장치이자, 본문의 흐름을 끊지 않고 원자료의 추가 디테일과 반론을 싣는 보조 서술 공간으로 사용한다.

### 2. 입력 자료

근거 장부, 게시물·댓글 ID, 날짜, 테이블, 분류, 최종 문장.

### 3. 작업 절차

다음 주장에는 반드시 각주를 붙인다.

- 수치·금액·점수·기간·연도
- 특정 기관·학교·로펌·제도의 정책이나 관행
- 특정 사건의 발생
- 증가·감소·확산·소멸·변화
- 대다수·우세·공통·예외적 같은 분포
- 대표 경험 사례와 원문 은어
- 상반된 입장과 댓글에만 있는 정정·반박

각주로 입증한 내용을 곧바로 풀어 쓰는 문장, 문서 구성 안내, 단순 전환문, 정의된 용어의 재사용은 별도 각주 없이 허용할 수 있다.

같은 명제를 지지하는 ID를 한 각주에 묶을 수 있지만 개수 할당량은 두지 않는다. 한 개의 고품질 스레드가 제도·행위·결과를 충분히 설명한다면 그 한 스레드를 길게 활용할 수 있다. 여러 저정보 게시물을 묶어 인용 수를 채우지 않는다.

각주 정의에는 ID만 적지 말고, 본문 판단을 가능하게 한 핵심 디테일을 요약한다. 각주는 다음 네 기능을 겸할 수 있다.

1. `출처 각주`: ID·날짜·분류와 본문 주장을 직접 뒷받침한 내용을 밝힌다.
2. `세부 각주`: 집계창, 계산법, 업무 순서, 행위자의 실제 선택처럼 본문에 모두 넣으면 흐름이 늘어지는 디테일을 보존한다.
3. `트리비아 각주`: 원문의 인상적인 비유·은어·당사자 표현·작은 후일담을 소개하되, 객관적 사실과 주관적 표현을 구분한다.
4. `논쟁 각주`: 작은 반례, 용어 정정, 적용 한계, 출처의 이해관계를 기록한다.

한 각주가 출처와 세부·트리비아를 함께 담아도 된다. 본문에 중요한 결론을 숨겨 각주만 읽어야 이해되게 해서는 안 되지만, 각주를 모두 읽은 독자는 원문을 다시 펼쳐 본 것에 가까운 추가 정보를 얻어야 한다. 통상 2~5문장까지 허용하며, 정보가 많으면 사실·반론·트리비아를 서로 다른 각주로 나눈다. 동일 게시물도 서로 다른 문장에서 서로 다른 세부를 뒷받침한다면 `[^G-P-123-detail]`, `[^G-P-123-trivia]`처럼 접미사를 붙여 여러 각주로 사용할 수 있다. 접미사 앞의 프로젝트·테이블·ID는 유지한다.

반론 댓글이나 후속 결과가 중요하면 같은 각주에 부모 글과 댓글 ID를 함께 적거나 별도의 댓글 각주로 떼어 본문 문장에 직접 연결한다. 각주의 수를 목표치로 정하지는 않지만, 긴 문서에서 모든 각주가 ID와 1문장 요약뿐이라면 나무위키형 보조 서술층이 구현되지 않은 것으로 본다.

### 4. 산출물

문장-각주 대응이 완전하고, 고급 원자료의 세부 맥락·비유·반례·후일담을 보존하는 주석형 각주.

### 5. 완료 조건

각 구체 주장을 DB 레코드까지 역추적할 수 있다.

### 6. 금지사항

URL·개인정보 노출, 서로 다른 주장의 무차별 결합, 댓글만으로 전체 경향 단정, 제목만 읽고 인용, 무관한 인용, ID만 나열하고 내용 요약이 없는 각주, 본문을 그대로 반복하는 각주, 출처 표시만 있고 추가 정보가 없는 각주만으로 문서를 채우기, 객관적 사실처럼 출처의 농담·과장을 재생산하기, 핵심 결론을 각주에 숨기기, 인용 개수 할당량 채우기.

### 7. 다음 모듈과의 연결

M4의 근거 장부로 각주 관계를 관리한다.

## M4 — DB 활용과 근거 장부

### 1. 목적

최종 문장과 DB 원문 사이에 검증 가능한 중간 계층을 둔다.

### 2. 입력 자료

대상 문서, 대응 소분류, 해당 댓글, 인접 소분류, 기존 노트의 ID.

### 3. 작업 절차

근거 장부는 저장소 밖 `C:/Users/USER/Documents/Codex/GRAD_ABROAD_EVIDENCE/{문서ID}/`에 Markdown 또는 CSV로 보존한다. 미완료 핸드오프도 같은 폴더의 `HANDOFF.md`에 둔다. 폴더가 없으면 최초 실행 시 생성할 수 있으나, DB나 게시 문서 구조는 바꾸지 않는다.

DB 탐색은 대표성 표집이 아니라 다이아몬드 탐색으로 수행한다. 기존 노트에 적힌 ID만 재확인하지 말고, `manual_score`, `info_score`, 본문 길이, 댓글 수를 후보 신호로 사용해 고정보 스레드를 다시 찾는다. 점수가 높다는 이유만으로 채택하지 말고 본문과 댓글을 읽어 실제 정보가치를 판단한다.

필수 필드:

| 필드 | 내용 |
|---|---|
| claim_id | `C01` 등 |
| target_section | 최종 목차 위치 |
| proposed_claim | 최종 문장 초안 |
| epistemic_type | 경험담/반복경험/통념/논쟁/편집자종합 |
| project/table/record_id | 근거 위치 |
| parent_post_id | 댓글인 경우 필수 |
| issued_at | 날짜 |
| primary/sub_category | 분류 확인 |
| stance | 지지/반대/예외/배경 |
| evidence_note | 직접 확인한 요지 |
| source_value | A 핵심 앵커/B 보조/C 제외 |
| concrete_details | 절차·수치·행동·결과·비유 등 보존할 디테일 |
| mechanism | 왜 그런 결과가 생기는지 원문이 제공하는 설명 |
| editorial_use | 본문에서 이 근거로 무엇을 설명할지 |
| source_limit | 단일 경험·추정·시점 한계·이해관계 |
| privacy_flag | 없음/익명화/사용금지 |
| verified | 본문·댓글·분류·날짜 확인 상태 |

정보가치는 다음 기준으로 판단한다.

- A급 핵심 앵커: 내부 절차나 작동 원리를 구체적으로 설명하고, 행위자의 선택·결과·반론 중 둘 이상을 포함한다.
- B급 보조: 앵커의 일부를 확인하거나 유용한 예외·후속 결과를 제공한다.
- C급 제외: 단순 질문, 감정 표출, 무근거 단정, 이미 알려진 말을 반복할 뿐 추가 디테일이 없다.

한 A급 스레드는 여러 C급 게시물보다 우선한다. 다만 A급 단일 경험을 전체 업계의 사실로 확대하지 않고 적용 범위를 문장에 표시한다.

댓글은 본문이 질문뿐일 때, 반박·예외가 필요할 때, 후속 결과가 댓글에 있을 때, 수치·절차가 정정될 때, 반응 양상이 통념 판단에 필요할 때 확인한다.

핵심 사례는 정보가치 순으로 먼저 고른 뒤, 빠진 시기·입장·예외가 있는지 보완한다. 시기별 균형을 맞추기 위해 저정보 글로 핵심 사례를 교체하지 않는다. 동일 사건 전재나 중복 저장본은 하나로 계산한다. 다른 소분류의 글은 대상 주장을 직접 다루고 문서 범위를 흐리지 않으며 원 분류와 사용 이유를 장부에 기록할 때만 쓴다.

`source_url`, 실명, 연락처, 이메일, 개인 프로필, 사건 특정 가능성이 큰 세부사항은 최종 문서에 넣지 않는다.

### 4. 산출물

주장-게시물-댓글 대응표, A급 앵커 목록, 본문에 반드시 보존할 디테일 목록, 사용 금지 근거 목록.

### 5. 완료 조건

모든 각주가 장부의 검증된 행과 연결되고, 각 대절에 적어도 하나의 A급 앵커 또는 이에 준하는 구체 자료가 사용된다.

### 6. 금지사항

DB 수정, 고아 댓글 인용, 댓글 분류 추정, 중복본을 복수 근거로 계산, 원문 전문 복제, 단순 빈도만을 이유로 C급 게시물을 본문 중심에 배치.

### 7. 다음 모듈과의 연결

장부의 날짜·입장을 M5에 사용한다.

## M5 — 시계열과 논쟁 서술

### 1. 목적

실제 변화와 시기별 잡음을 구분하고 논쟁을 균형 있게 배열한다.

### 2. 입력 자료

날짜·입장이 검증된 근거 장부와 반례.

### 3. 작업 절차

시기 구분은 이전과 이후에 복수 근거가 있고, 변화 대상이 명확하며, 관행·인식·환경의 실질 차이가 확인될 때만 한다. 한 사건은 시대가 아니라 해당 연도의 사례로 쓴다.

장기 통념과 일시적 화제는 단순 게시물 수보다 내용의 연속성을 본다. 서로 다른 시기의 현직 경험담이 동일한 작동 원리를 설명하면 장기 관행 후보가 된다. 한 시기에 제목만 비슷한 질문이 몰렸다면 유행이나 정보 공백일 수 있으므로 통념으로 격상하지 않는다.

논쟁은 `공통 배경 → 상대적으로 많이 확인되는 견해 → 반대 견해 → 적용 조건 → 반례 → 판단 가능한 범위` 순서로 서술한다.

오래된 정보는 `2010년대 초 게시물에서는 …가 언급되었다. 현재도 유지되는지는 최신 자료에서 확인되지 않는다.`처럼 기간과 불확실성을 표시한다. `현재` 대신 `2026년 8월까지의 게시물 기준`처럼 자료 종료 시점을 쓴다.

### 4. 산출물

시기 구분표와 논쟁 절.

### 5. 완료 조건

각 시대와 각 입장이 검증된 근거를 가진다.

### 6. 금지사항

게시물 수가 많은 해를 자동 전환점으로 지정, 최신 글 하나로 현재 관행 단정, 오래된 정보 삭제·혼합, 소수 견해를 논파된 견해로 처리.

### 7. 다음 모듈과의 연결

범위를 넘는 내용은 M6의 관련 문서로 연결한다.

## M6 — 내부링크와 문서 체계

### 1. 목적

기존 링크 그래프를 보존하면서 중복 설명을 줄인다.

### 2. 입력 자료

기존 파일명·링크, 관문, 대주제별 노드 목록.

### 3. 작업 절차

기존 파일명·경로·링크 대상과 별칭을 원칙적으로 보존한다. 다른 문서의 핵심 주제가 처음 나오거나 별도 설명이 필요한 경우 본문에 링크한다. 같은 대상은 한 절에서 최초 1회만 링크한다.

다른 문서의 핵심 내용을 2문단 이상 설명해야 한다면 1~3문장만 남기고 관련 문서로 넘긴다. 탐색은 `관문 → 대주제 묶음 → 세부문서 → 인접 세부문서`가 되게 한다. 별도 대주제 문서는 전체 세부문서가 안정된 후에만 신설을 검토한다.

### 4. 산출물

보존 링크와 신규 본문 링크 목록.

### 5. 완료 조건

기존 링크가 끊기지 않고 관문 또는 인접 문서로 이동할 수 있다.

### 6. 금지사항

파일명 변경, 링크 별칭 제거, 과도한 링크, 존재하지 않는 대상 링크, 동일 설명 복사.

### 7. 다음 모듈과의 연결

## M7 — 문서 하나의 변환 절차

### 1. 목적

다른 세션이 한 문서를 독립적으로 변환·검수할 수 있게 한다.

### 2. 입력 자료

대상 Markdown, 대응 DB, 관문, 관련 문서, 이 규격과 템플릿.

### 3. 작업 절차

1. 프로젝트, 경로, 문서ID, 테이블, 대·소분류를 고정한다.
2. 변환 전 파일명·frontmatter·링크 대상을 기록한다.
3. 기존 문서 전체를 읽고 주장·변화·논쟁·사례·오분류를 분리한다.
4. 기존 ID와 원본건수를 DB에서 재검증한다.
5. DB에서 고정보 후보를 다시 탐색한다. `manual_score`, `info_score`, 본문 길이, 댓글 수, 주제 키워드는 후보 선별에만 쓰고 본문·댓글 전문을 읽어 A/B/C를 판정한다.
6. 각 A급 스레드에서 절차, 숫자, 행위자, 선택, 결과, 반론, 예외를 추출한다.
7. 핵심 질문을 3~10개로 정리하고 인식론적 수준과 정보가치를 부여한다.
8. M4 근거 장부와 `반드시 보존할 디테일` 목록을 작성한다.
9. 분포가 아니라 작동 원리와 쟁점을 중심으로 새 목차를 확정한다.
10. 편집자의 판단-작동 방식-결과-반론-사례 순서로 본문을 쓴다.
11. 각 A급 원자료를 다시 보며 중요한 디테일이 일반론으로 소거되지 않았는지 역압축 감사를 한다.
12. 구체 사실 직후에 주석형 각주를 배치하고, 본문에서 덜어 낸 세부 절차·비유·용어 뉘앙스·작은 반례·후일담·출처 한계를 각주에 보존한다.
13. `tags`, `문서ID`, `원본건수`, `password`, 기존 링크를 보존하고 `최종수정`만 실제 작업일로 갱신한다.
14. 자동 검사와 원문 스팟체크를 실행한다.
15. diff에서 개인정보·URL·링크 손실을 확인한다.

### 4. 산출물

최종 문서 1개, 외부 근거 장부 1개, 검사 결과 1개.

### 5. 완료 조건

M8 필수 항목이 모두 통과한다.

### 6. 금지사항

여러 대형 문서 동시 재작성, DB 확인 생략, 사후 각주 끼워 맞추기, 원본건수 추정 변경, 승인 없는 배포, 기존 분석노트를 문장형으로만 바꾸기, 고정보 스레드를 일반적 경향 한 문장으로 압축하기.

### 7. 다음 모듈과의 연결

## M8 — 자동·수동 품질검사

### 1. 목적

구조·근거·메타데이터·문체 결함을 완료 전에 발견한다.

### 2. 입력 자료

수동 검사:

3. 논쟁의 다수 견해·반론·예외 왜곡 여부
4. 개요와 본문의 결론 반복 여부
5. 독자 질문 중심 목차 여부
6. 은어 최초 설명과 평가체 제거
7. 기존 분석노트 없이 이해 가능한지 통독
8. 각 대절에서 독자가 새로 얻게 되는 구체 정보가 무엇인지 한 문장으로 답하기
9. A급 앵커의 절차·행위·결과·반론이 본문 또는 각주에 보존되었는지 역압축 감사
10. `반복된다·두드러진다·논의된다`를 지웠을 때 남는 정보가 있는지 확인
11. 각주를 가리고 읽어도 본문의 핵심 논지가 완결되는지 확인
12. 각주만 훑어도 본문에 없는 세부·비유·예외·출처 한계를 새로 얻을 수 있는지 확인

## 3. 전체 우선순위 평가

각 항목은 0~4점으로 평가한다. `총점 = Σ(점수/4 × 가중치)`다.

| 항목 | 가중치 | 4점 기준 |
|---|---:|---|
| 독자 의사결정 가치 | 20 | 실제 선택·평가·행동을 바꾸는 정보 |
| 고정보 자료 밀도 | 25 | A급 앵커가 여러 개 존재 |
| 작동 원리의 구체성 | 20 | 절차·행위자·결과·부작용을 설명 가능 |
| 링크 중심성 | 10 | 여러 노드가 참조하거나 관문 핵심 위치 |
| 시계열·논쟁 가치 | 10 | 변화와 반론이 구체 자료로 확인됨 |
| 현 구조의 개선 필요 | 5 | 분석노트가 고급 정보를 심하게 압축함 |
| 후속 문서 선행효과 | 10 | 먼저 완성하면 다수 문서의 중복 감소 |

문서 규모는 작업량 산정에만 쓰고 정보가치 점수에는 넣지 않는다. G-015 교정 문서와 시범 4개는 점수와 무관하게 선행하고, 리뷰는 대응 일반 노드 뒤에, 관문은 세부문서 뒤에 처리한다.

## 4. 표준 각주 형식

```markdown
게시물에서는 컨펌을 인턴 이후 정식 채용이 확정되는 단계로 사용한다.[^G-P-1853462]

[^G-P-1853462]: GRAD DB `curated_posts.id=1853462`, 작성일 YYYY-MM-DD, 분류 `law_firm_workplace/firm_comparison`. 이 글에서 컨펌이 어떤 절차와 결과를 가리키는지 1~3문장으로 요약한다.
```

```markdown
이 조언에는 실제 경험을 바탕으로 한 반론도 제시되었다.[^A-C-778899]

[^A-C-778899]: ABROAD DB `curated_comments.id=778899`, 실제 부모 게시물 `curated_posts.id=445566`, 작성일 YYYY-MM-DD. 댓글이 반박한 전제와 추가한 예외를 요약한다.
```

```markdown
이 문제는 서로 다른 시기의 게시물에서 반복적으로 언급된다.[^A-P-recurring]

[^A-P-recurring]: ABROAD DB `curated_posts.id=111111`, `curated_posts.id=222222`, `curated_posts.id=333333`. 세 글에서 공통으로 확인되는 작동 방식과 서로 다른 조건을 요약한다.
```

```markdown
게시판에서는 A 견해가 반복되지만 B 조건에서는 반대 경험도 보고된다.[^G-P-dispute]

[^G-P-dispute]: GRAD DB `curated_posts.id=111111`과 `curated_posts.id=222222`는 A 견해의 논거를 제공하며, `curated_posts.id=333333`은 그 논거가 성립하지 않는 B 조건을 설명한다.
```

게시물과 핵심 댓글을 함께 설명하는 스레드는 `G/A-T-ID`를 쓴다. 리뷰 게시물은 `G-RP-ID` 또는 `A-RP-ID`를 쓴다. 모든 각주 정의는 ID와 함께 본문 판단에 쓰인 구체 내용을 요약해야 한다.
