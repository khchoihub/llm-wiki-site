# V3 다이아몬드 채굴형 문서 변환 파이프라인

이 문서는 V2 감사에서 드러난 발견 실패와 자기평가 편향을 보완한다. `README.md`와 충돌하면 이 문서가 우선한다.

## V3의 핵심 단위

V2는 게시물과 주장을 중심으로 관리했다. V3는 다음 네 단위를 분리한다.

1. 주제 질문(theme question): 독자가 실제로 이해해야 할 문제
2. 앵커 스레드(anchor thread): 작동 원리와 디테일을 제공하는 고급 원자료
3. 정보단위(information unit): 원자료에서 보존할 원자적 사실·절차·행동·결과·반론
4. 편집 논제(editorial thesis): 여러 정보단위를 묶어 편집자가 제시하는 해석
5. 보조 주석(annotation layer): 본문 논지를 방해하지 않으면서 세부·트리비아·반례·출처 맥락을 보존하는 각주 서술층

게시물 수나 문장 수는 품질 단위가 아니다.

## P0 — 작업 고정

1. 대상 파일, 문서ID, DB 범위, 기존 링크와 frontmatter를 기록한다.
2. 기존 문서는 수정 전에 별도 기준본으로 보존하거나 git diff로 비교 가능하게 한다.
3. 기존 노트의 ID는 정답이 아니라 검색 시드로만 취급한다.
4. 문서 변환 전에 감사 폴더에 `DISCOVERY.md`, `SOURCE_CARDS.md`, `INFORMATION_UNITS.md`, `CLAIM_GRAPH.md`, `QA.md`를 준비한다.

## P1 — 주제 질문 지도

기존 노트의 불릿을 그대로 목차로 쓰지 않는다. 다음 질문에 답하는 4~12개의 주제 질문으로 바꾼다.

- 제도나 관행은 실제로 어떻게 작동하는가.
- 공식 명분과 체감 기능은 어디서 갈리는가.
- 행위자는 어떤 선택을 하고 무엇을 감수하는가.
- 표면적 지표가 숨기는 것은 무엇인가.
- 실패·이탈·성공을 가르는 조건은 무엇인가.
- 반론은 어느 전제를 공격하는가.
- 시대가 바뀌면서 작동 방식 자체가 달라졌는가.

각 질문에는 초기 검색어, 동의어, 은어, 반대어를 붙인다. 예: `타임 → 빌러블, 평정, 성과급, 동결, 프리라이더, 업무배분`.

## P2 — 다중경로 후보 발견

반드시 `tools/mine_grad_abroad_sources.py`를 사용해 다음 경로의 합집합을 만든다.

1. 기존 노트에 인용된 ID
2. manual_score·info_score 상위
3. 본문이 긴 게시물
4. 댓글이 많은 스레드
5. 주제어가 제목에 있는 게시물
6. 주제어가 본문에 있는 게시물
7. 주제어가 댓글에 있는 스레드
8. 반론·예외 검색어가 있는 스레드

메타데이터 순위 하나만으로 후보를 자르지 않는다. 본문이 짧아도 댓글에 현직자의 장문 설명이 있으면 앵커가 될 수 있다.

### 후보 정독 순서

1. 두 개 이상의 검색 경로에 걸린 후보
2. 기존 ID 시드
3. 제목·본문·댓글 중 둘 이상에서 주제가 확인된 후보
4. 장문 또는 고댓글 후보
5. 메타데이터 상위 후보

## P3 — 주제별 포화 중단

후보 풀 전체를 기계적으로 전수정독하지 않는다. 주제별로 다음 조건을 모두 만족할 때 탐색을 멈출 수 있다.

1. A급 앵커가 2개 이상 확보됐거나, 대체 불가능한 단일 A급 자료와 독립 보조 근거가 있다.
2. 핵심 반론 또는 적용 한계가 최소 1개 확인됐다.
3. 마지막으로 새로운 정보단위가 나온 뒤 연속 5개 후보에서 새 정보단위가 나오지 않았다.
4. 제목·본문·댓글 검색 경로를 각각 최소 한 번 검토했다.
5. 시계열 주장이 있으면 초기와 최근 자료를 별도로 검색했다.

원본 49건 이하 문서는 원칙적으로 전량 읽는다. 포화는 `더 읽기 싫다`는 판단이 아니라 새 정보단위가 더 이상 나오지 않는다는 기록 가능한 판단이다.

## P4 — 앵커 스레드 카드

정독한 후보마다 다음을 기록한다.

| 필드 | 내용 |
|---|---|
| thread_id | 게시물 ID |
| source_value | A/B/C |
| author_position | 본문에서 확인되는 범위의 당사자 위치 |
| concrete_procedure | 실제 절차·집계·적용 방식 |
| actors | 관련 행위자와 권한 |
| choice | 당사자가 택한 행동 |
| consequence | 결과·부작용·후속 경로 |
| mechanism | 작성자가 설명한 인과 또는 작동 원리 |
| counterclaim | 댓글·본문의 반론 |
| limit | 단일 사례·추정·시점·이해관계 한계 |
| privacy | 삭제·익명화할 정보 |
| candidate_units | 추출할 정보단위 ID |

A급은 절차·행위자·선택·결과·반론 중 최소 세 요소를 구체적으로 제공하는 자료다. 단순 장문이나 높은 추천 수만으로 A급이 되지 않는다.

## P5 — 정보단위 장부

초안을 쓰기 전에 앵커를 원자적 정보단위로 분해한다.

```text
IU-TIME-01 | 절차 | 최근 14일 타임 합계가 전체 순위로 공개됨 | post 1872877/comment 13677062 | critical
IU-TIME-02 | 결과 | 업무 이전 사정은 숫자에 표시되지 않아 동료 원망을 유발 | post 1872877 | critical
IU-TIME-03 | 반론 | 전체 공개는 상호 감시를 이용한 관리라는 해석 | comment 13676756 | supporting
```

필수 필드:

- `unit_id`
- `type`: 절차/수치/행동/결과/메커니즘/반론/예외/시기
- `content`
- `source_ids`
- `importance`: critical/supporting/context
- `target_claim`
- `retained_location`
- `omission_reason`
- `presentation_layer`: 본문/세부각주/트리비아각주/논쟁각주

critical 정보단위는 개인정보나 중복 문제가 없는 한 모두 본문 또는 각주에 남긴다.

## P6 — 편집 논제와 주장 그래프

목차를 쓰기 전에 각 대절을 다음 그래프로 설계한다.

```text
편집 논제
├─ 작동 원리
│  ├─ 정보단위
│  └─ 정보단위
├─ 당사자 결과
├─ 가장 강한 반론
├─ 적용 범위·예외
└─ 각주 묶음
```

좋은 논제는 `무엇이 언급된다`가 아니라 `무엇이 어떤 경로로 어떤 결과를 만든다`를 말한다. 정보단위를 연결하는 해석은 허용하되, 원문 사실과 편집자 추론을 문장 수준에서 구분한다.

## P7 — 초안 작성

1. 각 대절 첫 문장은 편집 판단을 제시한다.
2. 전환문을 제외한 각 문단에는 서로 다른 정보단위가 원칙적으로 2개 이상 있어야 한다.
3. 문서의 결론과 핵심 메커니즘은 본문에 둔다. 세부 집계법·보조 계산·원문의 비유와 은어·작은 반례·후일담·출처의 자기규정과 한계는 각주에 두어 이중 서술층을 만든다.
3-1. 각주는 단순 출처 표식이 아니다. `DB 위치 + 본문에 없는 추가 정보`를 기본형으로 하며, 정보가 풍부하면 한 원문을 사실 각주와 트리비아·반론 각주로 나눈다.
3-2. 원문의 과장·농담·은어는 `작성자의 표현`, `주관적 비유`라고 표시한다. 정보가치가 있더라도 혐오·개인식별·명예훼손 위험이 있는 트리비아는 싣지 않는다.
4. `반복된다`, `두드러진다`, `논의된다`는 빈도 자체가 역사적 정보일 때만 쓴다.
5. A급 단일 경험은 범위를 표시해 충분히 자세히 쓴다.
6. C급 자료는 도입부나 결론의 중심 근거로 쓰지 않는다.

## P8 — 적대적 반론 검색

초안의 각 핵심 논제에 대해 다음을 별도로 검색한다.

- 반대 결과
- 다른 원인
- 다른 조직·학교·시기
- 당사자와 관리자의 상반된 관점
- 예외적으로 성공하거나 실패한 경로
- 원 지표의 측정 오류 또는 조작 가능성

반론을 찾지 못했으면 `반론 없음`이 아니라 검색어와 검색 범위를 기록한다. 강한 반론이 나오면 논제를 약화하거나 조건부로 다시 쓴다.

## P9 — 삼중 감사

### A. 근거 정밀도

- 모든 구체 사실의 DB 근거 존재: 100%
- 댓글 부모 일치: 100%
- 원문에 없는 수치·사건: 0개
- 편집자 추론의 사실 위장: 0개

### B. 정보 보존

- critical 정보단위 보존: 100% 또는 명시적 제외 사유
- A급 전체 정보단위 보존율: 85% 이상
- 각 대절에 작동 원리·실무 디테일·의사결정 함의 중 2개 이상
- 주석형 각주: ID와 실질 요약 모두 포함
- 핵심 각주 중 일부는 본문에 없는 세부·비유·예외·출처 한계를 제공
- 각주를 제거해도 본문의 논지는 완결되고, 각주를 읽으면 추가 정보가 생김

### C. 적대적 검토

- 논쟁적 대절마다 가장 강한 반론 또는 한계 존재
- 반론 검색 로그 존재
- 단일 경험의 범위 표시
- 기존 노트의 프레임을 그대로 답습하지 않았는지 확인

## P10 — 블라인드 비교 판정

교정 문서와 중요 문서는 초안 작성자가 제목을 가린 두 버전을 비교한다.

- A: 기존 또는 이전 규격 문단
- B: V3 문단

다음 질문에 각각 0~2점을 준다.

1. 실제 절차를 설명하는가.
2. 행위자의 선택과 제약을 설명하는가.
3. 결과가 생기는 메커니즘을 설명하는가.
4. 반론이 구체적인가.
5. 각주가 출처 표시를 넘어 세부·트리비아·반례·한계를 제공하는가.
6. 읽은 뒤 실제 판단이 달라질 정보가 있는가.

V3가 10/12 이상이고 이전 버전보다 4점 이상 높아야 교정 통과다. 동일 작성자의 자기평가임을 감안해 사용자가 교정 문서 1개를 최종 승인해야 대량 전환을 시작한다.

## P11 — 상태 갱신

1. 자동 검사, 정보단위 감사, 반론 검색, 블라인드 비교를 모두 통과한 문서만 완료로 표시한다.
2. 이전 규격 완료 문서는 자동으로 완료 승계하지 않고 V3 재감사를 한다.
3. G-015 교정 문서가 사용자 승인을 받기 전에는 77개 대량 전환을 재개하지 않는다.
4. 배포는 별도 명시가 있을 때만 한다.
