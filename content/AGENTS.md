# LLM Wiki — 정책학 (Policy Studies)

개인 연구용 문헌 지식 베이스.

**핵심 4축:** 정책피드백이론(Policy Feedback Theory), 공공서비스동기(PSM), 관료적저항(Bureaucratic Resistance), 민군관계(Civil-Military Relations).

**확장축 (실제 누적된 연구 범위):** 정책과정론(의제설정·집행·정책변동·옹호연합·다중흐름), 정책분석·증거기반정책, 공공행정학(행정책임·관료제·정치행정이원론), 신공공관리론·성과관리·거버넌스, 인사행정(실적제·다양성관리), 조직이론·신제도주의, 합리적선택·행동경제학, 비판적담론분석, 연구방법론(도구변수·인과추론). 군인사정책·전쟁법은 카테고리 골격만 마련, 논문 추가 대기.

---

## 4대 원칙 (절대 위반 금지)

1. **웹 검색 금지.** `WebSearch`·`WebFetch`로 내용을 채우지 않는다. 모든 답변은 실제 보유 논문에 근거한다.
2. **위키 우선 답변.** `wiki/`가 유일한 진실의 원천이다.
3. **위키가 부족하면 PDF 재독.** `papers/{파일명}.pdf`를 `pypdf`로 재추출한 뒤 위키를 업데이트한다.
4. **논문이 없으면 솔직히 말한다.** *"이 주제의 논문이 없습니다 — PDF를 주세요."* 즉흥 답변 금지.

---

## 서술 언어

- **위키 내 모든 서술: 한국어.** 주요 학술 용어는 괄호에 영문 병기. 예: 정책피드백(Policy Feedback)
- **백링크 개념 노드: 한국어만.** 괄호 없이. 예: `[[관료적저항]]`
- 대화는 어떤 언어든 가능.

## 투 트랙 구조

```
트랙 A (안정적 뼈대)              트랙 B (누적 논문)
─────────────────                ──────────────────
교과서 기반 개념 정의              개별 논문 분석 노트
잘 바뀌지 않음                    계속 쌓임
wiki/01_개념노트/                 wiki/02_논문노트/
                                         ↓
                             5편 누적 시 합성 → 트랙 A 업데이트
```

- 트랙 B 논문 노트에 핵심 개념을 `[[관료적저항]]` 형식으로 표기
- **`[[링크]]` 생성과 파일 생성은 항상 함께.** 링크만 쓰고 파일을 만들지 않으면 백링크 그래프가 작동하지 않는다.
- 논문이 쌓일수록 개념 노드가 위키처럼 작동 (Obsidian 백링크)
- 메타분석 1편 = 일반 논문 3~5편 수준 → 메타분석 2편 누적 시 합성 가능

## 논문 추가 절차

### 1단계 — PDF를 구글 드라이브에 저장 후 텍스트 추출

PDF를 `G:\내 드라이브\llm-wiki-papers\{연도}_{저자}_{키워드}.pdf`로 저장.

```bash
python -c "
import pypdf, sys
reader = pypdf.PdfReader(sys.argv[1])
text = ''
for page in reader.pages[:15]:
    t = page.extract_text()
    if t: text += t + '\n'
    if len(text) > 12000: break
print(text[:12000])
" "G:/내 드라이브/llm-wiki-papers/{파일명}.pdf"
```

### 2단계 — 트랙 B 노트 작성

위의 마스터 프롬프트로 `wiki/02_논문노트/{연도}_{저자}_{키워드}.md` 생성.

### 3단계 — 논문 색인 업데이트

트랙 B(논문) 전수 색인은 `wiki/00_INDEX/논문노트_전체목록.md`에 있다. 해당 분야 아래 한 줄 추가.
(루트 `index.md`는 전수 나열이 아닌 **관문(gateway)**이다 — 논문을 직접 나열하지 않는다. 개념 노트만 트랙 A에 등록.)

### 4단계 — 개념 노트 연결 확인 (필수, 건너뛰기 금지)

논문 노트 작성 완료 후 **반드시** 아래를 실행한다.

**4a. 새 [[링크]] 파일 존재 여부 확인**

논문 노트의 `관련 개념 노드` 섹션에 쓴 모든 `[[개념명]]`에 대해:
```
wiki/01_개념노트/**/{개념명}.md   ← 이 파일이 존재하는가?
```
- **존재하면**: 통과
- **없으면**: 즉시 신설 (아래 기준 적용)

**4b. 개념 노트 신설 기준**

| 조건 | 처리 |
|------|------|
| 위키 핵심 주제(PSM·관료적저항·민군관계·정책피드백 등) | 반드시 신설 |
| 2편 이상의 논문 노트에서 공통 참조 | 신설 |
| 논문 1편에서만 등장하는 소개념 | 일반 텍스트로 남김, `[[]]` 제거 |
| 논문 파일명 자체(`[[2024_저자_키워드]]`) | `[[]]` 즉시 제거, 일반 텍스트 처리 |

## PDF 관리 원칙

### 신규 논문
- 새로 발견한 논문은 `G:\내 드라이브\llm-wiki-papers\`에 넣는 것을 권장. **파일명 형식은 무관** — Codex가 키워드 검색으로 알아서 찾는다.
- 파일명 예시: `Mettler 2024.pdf`, `lipsky_slb_ch3.pdf`, `정책피드백논문.pdf` 모두 처리 가능.

### 기존 흩어진 논문·교과서
- G드라이브 어느 경로든 **복사 없이 원위치에서 처리 가능**. 경로만 알려주면 된다.
- 예: "G:\수업자료\Lipsky_ch3.pdf 노트 만들어줘"
- 폴더째로 처리: "G:\내 드라이브\수업자료\ 폴더 훑어서 위키에 없는 것 노트 만들어줘"

### 교과서 챕터
- 교과서 챕터는 **트랙 A 개념 노트** 보강에 활용 (정의·이론적 맥락 섹션).
- PDF 경로 전달 또는 텍스트/이미지를 채팅에 직접 붙여넣기 모두 가능.

### 공통
- PDF 파일 자체는 GitHub에 올리지 않음.
- 연구실·다른 PC에서는 구글 드라이브 데스크톱 앱 설치 시 동일 경로 접근 가능.

## 세션 마무리 체크리스트 (매 세션 종료 전 필수 실행)

아래 체크리스트를 세션 끝마다 반드시 실행한다. 생략 시 dangling link 부채가 누적된다.

### 체크 1 — Dangling Link 탐지
```bash
# 논문 노트의 [[링크]] 중 01_개념노트에 파일이 없는 것 탐지
grep -ohP '\[\[([^\]]+)\]\]' wiki/02_논문노트/*.md \
  | sed 's/\[\[\|\]\]//g' | sort -u
# → 각 이름에 대해 wiki/01_개념노트/**/{이름}.md 존재 여부 확인
```

### 체크 2 — 링크 이름 정규화 확인
금지 패턴이 남아 있으면 즉시 수정:
```bash
grep -rl "\[\[PSM\]\]"                     wiki/02_논문노트/
grep -rl "\[\[신공공관리론(NPM)\]\]"       wiki/02_논문노트/
grep -rl "\[\[비판적담론분석(CDA)\]\]"     wiki/02_논문노트/
grep -rl "\[\[역사적제도주의\]\]"          wiki/02_논문노트/
```

### 체크 3 — 합성 대상 개념 확인
5편 이상 누적된 개념의 `트랙B 합성 공간`이 채워져 있는지 확인.

### 체크 4 — index.md 동기화 (트랙 A + 트랙 B 모두)
1. **트랙 B**: 새 논문 노트(02_논문노트·03_메타분석노트·04_방법론)가 `wiki/00_INDEX/논문노트_전체목록.md` 해당 섹션에 추가되었는지 확인.
2. **트랙 A**: 새 개념 노트(01_개념노트)가 `index.md` 트랙 A 해당 섹션에 한 줄 등록되었는지 확인.

```bash
# 트랙A 미등록 개념노트 탐지: 01_개념노트에 있는 파일명이 index.md에 없으면 누락
Get-ChildItem wiki\01_개념노트 -Recurse -Filter "*.md" | ForEach-Object {
    $name = $_.BaseName
    if (-not (Select-String -Path index.md -Pattern "\[\[$name\]\]" -Quiet)) {
        Write-Host "누락: $name"
    }
}
```

### 체크 5 — 사이트 배포 (publish.ps1 실행) ← 반드시 마지막에

**매 세션 종료 시 아래 명령 1줄로 GitHub + 사이트를 동시 배포한다.**

```powershell
# llm-wiki 루트에서 실행
cd C:\Users\USER\Desktop\llm-wiki
.\publish.ps1 "간략한 변경 내용"
```

`publish.ps1`이 수행하는 4단계:
1. `llm-wiki` git add → commit → push (→ `khchoihub/llm-wiki.git`)
2. `robocopy /MIR` — llm-wiki → llm-wiki-site/content 완전 미러 (삭제 파일도 반영)
3. `npx quartz build` — 정적 사이트 빌드
4. `llm-wiki-site` git commit → push → GitHub Pages 자동 배포

> **주의**: `publish.ps1`을 실행하지 않으면 llm-wiki-site/content는 구버전으로 남는다.
> llm-wiki push ≠ 사이트 업데이트 — 반드시 publish.ps1 실행 필요.

## 저장소 관계 구조

```
C:\...\llm-wiki\          (소스 - 작업 공간)
   ↓  publish.ps1 실행 시 robocopy /MIR
C:\...\llm-wiki-site\content\   (Quartz 빌드 입력)
   ↓  npx quartz build
C:\...\llm-wiki-site\public\    (정적 파일)
   ↓  git push origin v5
GitHub Pages (https://khchoihub.github.io/llm-wiki-site)
```

**두 저장소는 별개 git repo — 자동 동기화 없음.**
`llm-wiki`에 커밋해도 사이트는 자동 업데이트되지 않는다.
`publish.ps1`이 이 간극을 수동으로 메운다.
