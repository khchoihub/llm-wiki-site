# Hermes-Codex 연구 파이프라인

## 핵심 목표

이 파이프라인의 목적은 `wiki/00_INDEX/정책학_논문주제.md`와 `wiki/00_INDEX/전쟁법_논문주제.md`를 지휘본부로 삼아, Hermes의 국내 문헌 API·초록 수집·원문 다운로드 능력을 활용해 여러 논문 프로젝트를 병렬로 진행하는 것이다.

사용자는 지휘자 역할을 맡는다. Hermes와 Codex는 사용자의 승인 없이 연구 방향을 확정하지 않는다.

## 0. 착수 입력

사용자는 `00_INBOX/`에 연구 질문을 남긴다.

예:

```text
주제: 한국형 사이버 예비전력과 민간 해커의 직접적 적대행위 참여
목표: 국내 문헌과 법령 자료를 모아 2주 내 초고 가능성 판단
우선 자료: 국내 논문, 국회 회의록, 법령, 정부 문서
제외: 단순 뉴스, 블로그, 출처 불명 자료
```

## 1. Hermes 수집

Hermes는 국내 문헌 API와 원문 다운로드 능력을 사용해 다음 산출물을 남긴다.

- `01_SEARCH_LOG/{YYYY-MM-DD}_{주제}_검색로그.md`
- `02_CANDIDATES/{YYYY-MM-DD}_{주제}_후보표.md`
- `03_ABSTRACTS/{YYYY-MM-DD}_{주제}_초록수집.md`
- `04_PDFS/{YYYY-MM-DD}_{주제}_PDF확보현황.md`

Hermes는 검색 결과를 대화로만 반환하지 말고, 반드시 파일로 저장한다.

Hermes 산출물은 `HERMES_OUTPUT_SCHEMA.md`의 필드를 따른다.

## 2. 후보 선별

Codex 또는 사용자는 후보 논문을 네 등급으로 나눈다.

| 등급 | 의미 | 처리 |
|---|---|---|
| A | 바로 읽고 논문노트화 | PDF 확보 후 `wiki/02_논문노트/` 승격 |
| B | 초록 기준 관련성 높음 | `05_READING_QUEUE/읽기대기열.md` 등록 |
| C | 배경문헌 가능 | 후보표에 유지 |
| D | 제외 | 제외 사유 기록 |

## 3. PDF 확보

PDF 원본은 다음 위치에 저장한다.

```text
G:\내 드라이브\llm-wiki-papers\
```

권장 파일명:

```text
{연도}_{제1저자성}_{핵심키워드}.pdf
```

`04_PDFS/`에는 실제 파일을 넣지 않고, 원본 경로와 확보 상태만 기록한다.

## 4. 논문노트 승격

읽은 논문은 기존 AGENTS.md의 트랙 B 규칙에 따라 `wiki/02_논문노트/`에 작성한다.

필수:

- 한국어 서술
- 주요 개념은 `[[개념명]]`
- 논문 파일명을 `[[링크]]`로 만들지 않기
- 새 개념 링크를 만들면 개념노트 파일도 함께 만들기
- `wiki/00_INDEX/논문노트_전체목록.md` 업데이트

## 5. 논문 초고화

주제별 초고는 `06_DRAFTS/{주제}/` 아래에 둔다.

권장 파일:

- `00_연구질문.md`
- `01_문헌지도.md`
- `02_자료목록.md`
- `03_분석틀.md`
- `04_목차.md`
- `05_초록.md`
- `06_서론.md`
- `07_초고.md`

초고 작성은 다음 조건을 만족한 뒤 시작한다.

- A 등급 핵심 문헌 5편 이상 또는 핵심 법령·공문서 5개 이상 확보
- PDF 원문 확인 또는 신뢰 가능한 원문 텍스트 확인
- `wiki/02_논문노트/` 또는 `06_DRAFTS/{주제}/01_문헌지도.md`에 근거 정리
- 사용자가 `08_GATES/승인체크리스트.md`의 "초고 착수 승인"을 통과시킴

## 6. 세션 종료 체크

작업 종료 전 확인한다.

- 새 후보가 `02_CANDIDATES/`에 남았는가?
- 읽을 논문이 `05_READING_QUEUE/읽기대기열.md`에 반영되었는가?
- PDF 경로가 `04_PDFS/`에 기록되었는가?
- 논문노트로 승격한 경우 `wiki/00_INDEX/논문노트_전체목록.md`가 업데이트되었는가?
- 논문주제 md가 최신 판단을 반영하는가?
- `PROJECTS.md`의 상태와 다음 행동이 갱신되었는가?
