# 진행중 연구 파이프라인

이 폴더는 논문 아이디어가 실제 원고로 이동하는 작업 공간이다. `wiki/`가 정리된 지식베이스라면, `ongoing_research/`는 아직 살아 움직이는 자료 수집, 후보 선별, 읽기, 초고 작성의 공간이다.

## 역할 분담

- Hermes: 국내 문헌 API 검색, 한국어 초록 수집, 원문 PDF 확보, 후보표 생성.
- Codex: 후보 선별, 논문노트 승격, 개념노트 연결, 목차와 초고 작성, 위키 동기화.
- Obsidian: 연구 흐름 확인, 백링크 탐색, 사람이 읽고 판단하는 작업대.

## 기본 흐름

1. `PROJECTS.md`에서 진행할 논문 주제를 고른다.
2. `00_INBOX/`에 연구 질문 또는 Hermes 작업 지시를 적는다.
3. Hermes가 `01_SEARCH_LOG/`, `02_CANDIDATES/`, `03_ABSTRACTS/`에 검색 결과를 남긴다.
4. 읽을 논문은 `05_READING_QUEUE/읽기대기열.md`로 승격한다.
5. PDF를 확보하면 원본은 `G:\내 드라이브\llm-wiki-papers\`에 저장하고, 이 폴더에는 경로와 메타데이터만 남긴다.
6. 논문으로 쓸 만한 문헌은 `wiki/02_논문노트/` 또는 `wiki/03_메타분석노트/`로 승격한다.
7. 특정 논문 주제의 목차와 초고는 `06_DRAFTS/`에서 관리한다.
8. 단계가 바뀔 때마다 `08_GATES/`의 승인 기준을 확인한다.
9. 논문 방향이 확정되면 `wiki/00_INDEX/정책학_논문주제.md` 또는 `wiki/00_INDEX/전쟁법_논문주제.md`를 업데이트한다.

## 폴더 구조

- `00_INBOX/`: 사람 또는 AI가 던진 연구 질문, 검색 지시, 아이디어.
- `01_SEARCH_LOG/`: Hermes/API 검색 로그.
- `02_CANDIDATES/`: 후보 논문 표와 선별 결과.
- `03_ABSTRACTS/`: 초록 묶음, API 응답 요약.
- `04_PDFS/`: PDF 원본 위치, 다운로드 여부, 파일명 대응표.
- `05_READING_QUEUE/`: 읽을 논문, 읽은 논문, 노트화 대기 목록.
- `06_DRAFTS/`: 논문별 목차, 초록, 서론, 초고.
- `07_AGENT_RUNS/`: Hermes, Codex 등 에이전트 실행 기록.
- `08_GATES/`: 단계별 승인 기준과 점검표.
- `99_ARCHIVE/`: 중단 또는 보류된 흐름.

## 운영 원칙

- 채팅창에만 남기지 않는다. Hermes가 찾은 결과는 반드시 이 폴더 안의 md/csv/json 중 하나로 남긴다.
- PDF 원본은 Git에 넣지 않는다. 원본은 Google Drive PDF 폴더에 두고 경로만 기록한다.
- 위키에 들어갈 만큼 정리된 내용만 `wiki/`로 승격한다.
- 초록만으로 논문 본문을 쓰지 않는다. 초록은 선별용이고, 본문 주장은 PDF 원문 또는 정식 논문노트에 근거해야 한다.
- 여러 논문을 동시에 굴릴 때는 반드시 `PROJECTS.md`의 상태를 갱신한다.
- 매 작업 종료 시 `05_READING_QUEUE/읽기대기열.md`와 관련 논문주제 md를 업데이트한다.
